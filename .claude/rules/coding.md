# コード規約（workspace のコード作業向け・汎用原則）

`workspace/` で JS/TS/Python 等を書くときの**汎用デフォルト**。特定ツール（パッケージマネージャ・
リンター・テスト等）は決め打ちしない。

> **最優先はプロジェクト側の既存設定・慣習**。`workspace/` 内の各プロジェクトに lockfile・
> 設定ファイル・独自の `AGENTS.md`/`CLAUDE.md`・スタイルガイドがあれば、**それらが本ファイルより優先**。
> ここは「プロジェクト側に指定が無いときのデフォルト」。

## 言語共通

- **既存に合わせる**: 周辺コードの命名・構造・イディオム・コメント量に倣う。新しい様式を持ち込まない。
- **小さく変更**: 依頼範囲に集中し、無関係なリフォーマットや一括整形をしない（差分を汚さない）。
- **テスト**: 既存のテスト基盤があれば、変更に対応するテストを追加・更新する。既存テストを壊さない。
- **設定ファイルを尊重**: リンター/フォーマッター/型チェッカ等の設定があれば従い、勝手に無効化・上書きしない。
- **依存追加は最小限**: 標準ライブラリ/既存依存で足りるなら足す前に検討。追加は Takumi Guard 経由（[AGENTS.md](../../AGENTS.md)）。
- **秘密情報を書かない**: APIキー・トークン・認証情報をコードやコミットに含めない（secretlint/gitleaks で検出される）。
- **エラーを握りつぶさない**: 例外・エラーは適切に処理/伝播する。空 catch や握り潰しの無視を避ける。
- **公開境界に型と説明**: 公開関数・モジュール境界は型とドキュメントを明確にする。

## JavaScript / TypeScript

- **パッケージマネージャは lockfile に従う**（`package-lock.json`/`pnpm-lock.yaml`/`yarn.lock` のあるものを使う）。勝手に乗り換えない。
- **リンター/フォーマッターに従う**（ESLint/Prettier/Biome 等、プロジェクトにあるもの）。設定外の全体整形をしない。
- **TypeScript は型を効かせる**: `any` を避け、既存の `tsconfig`（strict 等）に従う。型エラーを残さない。
- **モジュール様式を合わせる**: ESM/CJS はプロジェクトの既存方式に統一する。
- **テスト**: 既存フレームワーク（Jest/Vitest/node:test 等）に合わせて書く。

## Python

- **環境管理は既存方式に従う**（venv/uv/poetry など、プロジェクトが使っているもの）。
- **リンター/フォーマッターに従う**（ruff/black/flake8/isort 等、プロジェクトにあるもの）。設定外の全体整形をしない。
- **型ヒントを付ける**: 公開関数にはアノテーションを付け、型チェッカ（mypy/pyright 等）があれば通す。
- **依存管理様式を合わせる**（`pyproject.toml`/`requirements.txt` など、既存のものに追記する）。
- **テスト**: 既存フレームワーク（pytest/unittest 等）に合わせて書く。
